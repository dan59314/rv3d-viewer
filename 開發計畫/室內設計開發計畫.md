# RV室內設計開發計畫

## 1. 專案目標

建立全新且獨立的 Viewer Plugin：

- 顯示名稱：`RV室內設計`
- 專案名稱：`Rv3dViewer.PlugIn_RVInteriorDesign`
- Plugin ID：`rv3dviewer.rv-interior-design`
- 平台：Windows x64、.NET 8、WinForms
- 舊 `Rv3dViewer.PlugIn_InteriorDesign` 專案已移除；本專案不得引用其組件、命名空間或測試程式

主要目標：

1. 以參數化方式建立室內空間、建築構件、家具、電器與燈具。
2. 提供四視圖進行模型置放與編輯。
3. 提供本機及 CC0 線上模型、貼圖與材質庫。
4. 將設計成果完整匯入 MainForm 目前開啟的專案。
5. MainForm 必須保留模型、階層、Transform、貼圖、材質、燈光及參數化來源資訊。
6. 儲存 `.rv3dproj` 後，重新開啟必須能正確還原。

## 2. 最重要的 MainForm 專案整合

### 2.1 整合原則

RV室內設計不是獨立輸出工具，而是 MainForm 專案的內容編輯器。

使用者在 Plugin 內完成設計後，可執行：

- 匯入選取物件
- 匯入目前房間
- 匯入全部設計
- 更新先前匯入的室內設計
- 匯入全部並關閉 Plugin

匯入後，內容必須立即出現在：

- MainForm 場景樹
- MainForm Viewport
- 模型屬性
- Mesh 清單
- 材質清單
- 貼圖圖層
- 燈光清單
- 專案儲存資料

Plugin 完成匯入後必須呼叫 MainForm Plugin API：

- `NotifySceneChanged()`
- `MarkProjectModified()`
- 必要時更新目前選取項目
- 狀態列顯示匯入結果

### 2.2 匯入內容

每個匯入模型至少包含：

- `SceneModel`
- `SceneNode`
- `MeshData`
- `TransformState`
- `PbrMaterial`
- `MeshMaterialIndices`
- `SourceMeshIndices`
- 程序化幾何資料
- 模型名稱與唯一 ID
- 顯示與鎖定狀態
- 父子階層
- 資產來源資訊

貼圖必須完整保存：

- Base Color
- Metallic
- Roughness
- Normal
- Bump
- Ambient Occlusion
- Emissive
- Opacity
- Texture Stack
- Texture Layer
- Mapping Mode
- Offset、Scale、Rotation
- Wrap 與 Filter
- 色彩空間
- Normal／Bump 強度

材質必須完整保存：

- 名稱
- Base Color
- Metallic
- Roughness
- Opacity
- Emissive
- Transmission
- IOR
- Glass 模式
- 雙面顯示
- 所有貼圖通道
- Mesh 與材質的對應關係

燈具模型可同時匯入：

- 燈具外觀模型
- `SceneLight`
- 燈光類型
- 位置與方向
- 顏色與色溫
- 強度
- 範圍
- 內外照射角

### 2.3 可編輯資料與渲染資料

匯入 MainForm 時必須同時產生兩類資料。

#### 可直接渲染的模型資料

包含：

- 已產生的 Mesh
- 法線
- UV
- Tangent
- 材質
- 貼圖
- Transform

即使沒有載入 RV室內設計 Plugin，MainForm 仍應能顯示已匯入的模型。

#### RV室內設計參數資料

包含：

- 房間尺寸
- 牆體起終點
- 牆高與牆厚
- 門窗洞口
- 家具置放約束
- 原始參數化模型
- 資產來源
- 材質指定
- Plugin 文件版本

重新由 MainForm 開啟 RV室內設計時，可讀取這些資料繼續修改。

### 2.4 專案格式擴充

目前 `.rv3dproj` 需要增加通用 Plugin 擴充資料區，建議新增：

```csharp
Dictionary<string, JsonElement> Extensions
```

建議位置：

- `ViewerProject.Extensions`
- 或個別 `SceneModel.Extensions`

RV室內設計使用固定 Key：

```text
rv3dviewer.rv-interior-design
```

擴充資料不得直接依賴 WinForms 或 Plugin Assembly 型別，應使用可攜式 JSON。

建議資料結構：

```json
{
  "extensions": {
    "rv3dviewer.rv-interior-design": {
      "version": 1,
      "documents": [],
      "modelLinks": {}
    }
  }
}
```

MainForm 不認識此擴充資料時：

- 不得刪除
- 不得改寫
- 儲存時必須原樣保留
- 已產生的 Mesh 與材質仍可正常顯示

### 2.5 貼圖與外部資產處理

不可把網路暫存路徑或 Plugin Cache 絕對路徑直接寫入專案。

匯入流程必須透過 MainForm 的 `ProjectAssetService`：

1. 驗證模型與貼圖。
2. 計算檔案雜湊。
3. 複製到專案 `Assets`。
4. 建立專案相對路徑。
5. 更新模型與貼圖引用。
6. 再加入 `ViewerProject`。

建議目錄：

```text
Assets/
├─ Models/
│  └─ RVInteriorDesign/
├─ Textures/
│  └─ RVInteriorDesign/
└─ Licenses/
   └─ RVInteriorDesign/
```

尚未儲存的 MainForm 專案：

- 先使用 MainForm 管理的暫存資產區。
- 執行「另存新檔」時搬移到正式專案 Assets。
- 不得讓 Plugin 自行決定永久路徑。

### 2.6 重複資產處理

匯入時應避免重複複製：

- 模型依內容雜湊判斷。
- 貼圖依內容雜湊判斷。
- 材質依參數與貼圖組合判斷。
- 相同資產可由多個模型共用。
- 名稱相同但內容不同時自動加編號。
- 更新既有室內設計時，保留穩定 ID。

### 2.7 交易式匯入

匯入 MainForm 必須是單一可復原交易：

1. 建立匯入快照。
2. 驗證所有模型、材質、貼圖與燈光。
3. 複製資產。
4. 建立 MainForm 專案模型。
5. 建立材質與貼圖對應。
6. 加入燈光。
7. 寫入 Plugin 擴充資料。
8. 通知 MainForm 更新。
9. 將整次匯入加入 Undo。

發生錯誤或取消時：

- 不得留下半套模型。
- 不得留下無引用貼圖。
- 不得破壞既有 MainForm 專案。
- 必須回復匯入前狀態。

因此 Plugin API 需要補充：

- 專案資產匯入服務
- 專案編輯交易
- 選取控制
- Undo／Redo 整合
- Plugin 擴充資料存取

## 6. 網路模型、貼圖與授權

預設只接受：

- CC0
- Public Domain
- 使用者擁有再散布權的資產

優先來源：

- [Poly Haven](https://polyhaven.com/license)
- [ambientCG](https://docs.ambientcg.com/license/)
- [Kenney](https://kenney.nl/support)
- [Quaternius](https://quaternius.com/faq.html)

原則：

- 優先使用官方 API。
- 不執行未授權網頁爬取。
- 每筆資產保存作者、來源、授權、網址及確認日期。
- 授權不明的資產不得自動下載。
- 授權紀錄隨 MainForm 專案保存。
- 支援下載進度、取消與離線快取。
- 解壓前檢查路徑與檔案類型。

支援格式：

1. GLB／glTF
2. OBJ＋MTL
3. FBX
4. STL
5. 其他 Assimp 格式

匯入後統一：

- Y 軸朝上
- 公尺為單位
- 修正法線與 Tangent
- 保留材質槽
- 建立縮圖
- 計算面數
- 將資產交由 MainForm 管理
